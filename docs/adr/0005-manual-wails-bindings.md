# ADR-0005: Hand-maintained Wails binding mirrors

- **Status:** Accepted
- **Date:** 2026-07-01

## Context
Wails generates JS/TS wrappers for exported Go `App` methods (`frontend/wailsjs/`). These are regenerated by `wails dev` / `wails build`. During fast iteration we often add a Go method and want the frontend (and its mocks/tests) to see it without a full Wails regeneration cycle, which is slower and not always running.

## Decision
Treat `frontend/wailsjs/go/main/App.js`, `App.d.ts`, and `models.ts` as **mirrors we update by hand** when adding or changing a Go method, following the existing patterns — in addition to letting `wails dev`/`build` regenerate them. New methods must also be added to the test/e2e mocks (`frontend/src/test/mocks/wailsjs.ts` and `e2e/mock-bridge.ts`) so unit and e2e suites stay runnable without a real backend.

## Consequences
- **Easier:** frontend, types, and tests stay in sync immediately; tests/e2e run with no Go process or database.
- **Harder:** the binding contract is maintained in several places; forgetting one yields a runtime "method not found" or a failing mock. This is a known papercut and the reason it's written down.
- **Accepted:** the discipline is documented in `CLAUDE.md`'s "Wails binding contract" section; reviewers check that new Go methods updated all mirrors and mocks.
