## What is this

Snowy is a desktop PostgreSQL GUI client built with [Wails v2](https://wails.io/) — Go backend + React/TypeScript frontend bundled into a native app. The Go code exposes methods to the frontend via Wails bindings; the frontend calls them through auto-generated wrappers in `frontend/wailsjs/`.

## Commands

### Development
```bash
wails dev          # hot-reload dev mode (runs both Go and Vite)
```

### Build
```bash
wails build        # production binary with embedded frontend
cd frontend && npm run build    # TypeScript check + Vite build only
```

### Frontend tests
```bash
cd frontend && npm run test              # run vitest once
cd frontend && npm run test:watch        # watch mode
cd frontend && npx vitest run src/components/Sidebar.test.tsx  # single file
```

### Backend tests
```bash
go test .                                                                       # unit tests (no DB needed)
TEST_DB_URL=postgres://myuser:mypassword@localhost:5432/mydatabase go test .    # + integration tests
```

### E2E tests (Playwright)
```bash
npx playwright test                                              # all specs
npx playwright test e2e/sprint7-sidebar-drill-in.spec.ts        # single spec
# Playwright auto-starts the Vite dev server on :5173 if not already running
```

### Demo database
```bash
docker compose -f docker/docker-compose-postgresql.yml up -d
# credentials: postgres://myuser:mypassword@localhost:5432/mydatabase
```

## Architecture

### Backend (Go)
- `main.go` — Wails bootstrap; embeds `frontend/dist` at compile time
- `app.go` — `App` struct with all exported methods bound to the frontend; thin wrappers that delegate to services
- `config.go` — `ConfigManager` reads/writes `~/.snowy/config.json` via `sync.RWMutex`; holds `Project` and `Datasource` structs (passwords stored plain text)
- `db_service.go` — `DbService` opens a fresh `pgx` connection per call (no pooling); schema/table/column/key/FK/index/check introspection and query execution; completion cache via `sync.Map`
- `query_service.go` — saves/loads/lists/renames `.sql` files under `~/.snowy/queries/<dsId>/`
- `history_service.go` — appends query history to `~/.snowy/history/<dsId>.jsonl`, newest-first on read

### Frontend (React + TypeScript + Tailwind)
- `frontend/src/App.tsx` — root component holding all app state; two views: `connections` (ConnectionManager) and `workspace`
- `frontend/src/components/Sidebar.tsx` — lazy-loading tree: datasources → schemas → tables → sub-folders (columns · keys · foreign keys · indexes · checks). Each table node uses `SubFolder<T> = { open, items, loaded }`. Columns auto-open on first table expand; others load lazily on click and cache — no re-fetch on reopen.
- `frontend/src/components/QueryEditor.tsx` — CodeMirror SQL editor with DB-aware autocomplete
- `frontend/src/components/ResultsPanel.tsx` / `ResultsTable.tsx` — tabular results with pinnable tabs and CSV export
- `frontend/src/components/ConnectionManager.tsx` — datasource CRUD + test-connection form
- `frontend/src/components/TabBar.tsx` — query console tabs with dirty-state tracking
- `frontend/src/components/HistoryDrawer.tsx` — slide-out query history panel
- `frontend/src/lib/tokens.ts` — all colors/fonts as `T.*` → `var(--t-*)` CSS custom properties; never use hardcoded hex values in components
- `frontend/src/types.ts` — shared `Project` and `Datasource` interfaces mirroring Go structs
- `frontend/wailsjs/go/main/App.js` + `App.d.ts` — Wails JS bindings; regenerated by `wails dev`/`wails build`; **update manually** when adding new Go methods (follow the existing patterns)
- `frontend/wailsjs/go/models.ts` — TypeScript classes for all Go response types; update manually when adding new Go structs

### Wails binding contract
- Any exported `App` method is callable from the frontend via `window.go.main.App.*`
- After adding a Go method: update `App.js`, `App.d.ts`, and `models.ts` to match existing patterns
- Go nil slices serialize as JSON `null` — always use `make([]T, 0)` instead of `var items []T` in DB methods to ensure the frontend receives `[]`, not `null`

### Testing approach
- **Go unit tests**: file-system operations use `t.TempDir()` + `t.Setenv("HOME", tmp)` — no DB required; integration tests in `db_service_test.go` skip unless `TEST_DB_URL` is set
- **Frontend unit tests**: vitest + jsdom; Wails bridge mocked via `frontend/src/test/mocks/wailsjs.ts`, mapped by alias in `vitest.config.ts` — add new Go methods there when extending the API
- **E2E tests**: Playwright against the Vite dev server; `e2e/mock-bridge.ts` installs a `window.go` mock via `page.addInitScript` — add new Go methods there too; no real DB needed for e2e

## Key constraints
- Each DB call creates and closes its own `pgx.Conn` — no connection pool
- Config is written atomically but passwords stored in plaintext in `~/.snowy/config.json`
- `frontend/dist` must exist before `wails build` (embed fails otherwise); `wails build` handles this automatically; manual `go build` does not
- **Tailwind v4** (`@tailwindcss/postcss`): `frontend/src/style.css` must start with `@import "tailwindcss";` — the v3 `@tailwind base/components/utilities` directives don't load the default theme in v4, so `--spacing` stays undefined and every spacing/typography utility (`px-*`, `pl-*`, `gap-*`, `w-1.5`, `text-xs`, `h-[22px]`, …) silently compiles to nothing while static ones (`flex`, `shrink-0`) still work. `tailwind.config.js` is not auto-loaded in v4 (content is auto-detected); reference it with `@config` if ever needed. If a spacing class has no visible effect, grep the built CSS in `frontend/dist/assets/*.css` for the rule before assuming the class name is wrong.
